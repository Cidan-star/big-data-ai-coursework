1. 个人解释

把 Agent 想象成一个"会用工具的私人助理"：你说一句"帮我查一下明天北京到上海的航班，挑最便宜的"，它会自己想清楚要先查航班、比价、再整理成一句话告诉你，而不是只回一句"好的，我没办法查"。

这里的关键在于"自主"。一个普通的聊天机器人只会基于训练知识回答问题，而 Agent 会主动做事：决定要调哪个工具、按什么顺序调、结果不够好就调整策略再来一次，直到任务完成。这种"边想边做、错了再试"的能力，是 Agent 区别于传统程序和单纯 LLM 的根本特征。

2. 核心机制

Agent 系统通常由四类组件构成，按"思考—执行—反馈"的循环串联：

  1. 大脑（Reasoning）：以大语言模型作为推理引擎，负责理解目标、拆解步骤、判断当前进度。最常用的是 ReAct（Reason + Act）模式：模型先产出"思考"，再产出"行动"，再到"观察"外部反馈。
  2. 工具（Tools）：模型可调用的外部能力，如搜索引擎、计算器、代码执行、文件读写、API 调用。每类工具都用 function calling 协议描述其输入输出 schema。
  3. 记忆（Memory）：
    • 短期记忆：本次任务的对话 + 工具调用历史，进入模型的上下文窗口。
    • 长期记忆：持久化存储的用户偏好、过往任务结果，跨越会话保留。
  4. 规划与反思（Planning & Reflection）：高级 Agent 会先列子任务清单（planner），执行中审视失败原因后重新规划（reflect / replan），代表方法是 Reflexion、Plan-and-Execute。

精简伪代码描述一次 Agent 循环：

while 未达成目标:
    thought  = LLM("目标={goal}, 历史={history}, 输出: 思考 + 下一步动作")
    action   = parse_action(thought)         # 调工具 or 输出最终回答
    if action.is_final_answer: return action
    observation = execute(action)            # 真实执行工具
    history.append(thought, action, observation)

失败兜底通常包含：最大步数（避免死循环）、单步超时、人类审核 checkpoint。

4. 边界辨析

区分点Agent相邻概念
是否能调用外部工具 ✅ 多步调用、可循环 LLM：只能生成文本，不主动调工具
对话目标 完成任务（行动导向） Chatbot：产生回复（对话导向）
流程确定性 由 LLM 动态决定步骤 Workflow：预设固定 DAG，流程静态
自主程度 在授权范围内自行决策 Copilot：每次需人类触发、人类主导

4.1 vs Chatbot

Chatbot 只回答问题；Agent 在得到指令后可能真的去订机票、生成代码、改数据库。

用户对 Chatbot 说"帮我订明天的机票"，Chatbot 会回答"好的，您可以使用携程 App"，而 Agent 会真正调用航班查询工具并下单。

4.2 vs Workflow / DAG 编排

Workflow 在 Airflow、Prefect 里流程是工程师提前写死的；Agent 的步骤序列由 LLM 在运行时即时决定。

一个 ETL Workflow 永远按 A→B→C 跑；同一个数据异常场景，Agent 可能先调诊断工具、再决定是修数据还是重跑模型。

4.3 vs Copilot（副驾驶）

Copilot 把"主动权"牢牢握在人类手里（每次都让人来选/确认）；Agent 把决策权让渡给 AI。

GitHub Copilot 会等用户采纳建议再写下一段代码；Devin 直接拉分支、跑测试、提 PR。

1. 个人解释

把 Skill 想成公司新员工的"入职手册"：手册里写明他的岗位是什么、遇到什么任务要按什么流程处理、可以调用哪些内部系统。AI 模型出厂时只是"一个什么都不熟的通用助理"，给它加载 Skill，就像是瞬间填补某个领域的经验与流程。

Skill 既不是简单的提示词（一条一次性指令），也不是改模型参数的微调，而是在外部以结构化文件的形式，把"工作流程 + 知识 + 工具说明"打包，让 AI 在需要时主动调用。

2. 核心机制

2.1 文件结构

一个标准 Skill 由 SKILL.md 必备、可选的资源目录组成：

my-skill/ ├── SKILL.md ← 必备：元数据 + 指令正文 │ ├── YAML frontmatter ← name / description / agent_created │ └── Markdown body ← 触发场景、输入、步骤、输出 ├── scripts/ ← 可选：可执行脚本 ├── references/ ← 可选：按需加载的补充资料 └── assets/ ← 可选：模板、图标等产物资源

2.2 YAML 元数据

最关键的两个字段是 name 与 description。模型在每次推理时都会读到这两行（≈100 词），用于判断当前任务是否需要加载本 Skill 全文。

---
name: concept-learning
description: This skill should be used when the user
  provides a new concept and needs structured learning material...
---

2.3 三级渐进加载（Progressive Disclosure）

Skill 采用分级上下文管理，控制 token 成本：

  1. L1 元数据：常驻在系统 prompt，~100 词/技能，用于触发判断
  2. L2 正文：仅在元数据匹配上时加载，< 5K 词
  3. L3 资源：脚本可直接执行不占 context；references 按需 grep

2.4 触发机制

模型通常基于以下信号决定是否启用 Skill：

  • 描述匹配：用户自然语言是否命中 description 中的关键词
  • 显式调用：用户写 /skill-name 或在对话里 @ 提到
  • 相关性打分：模型对所有可见 Skill 做语义相关度排序，Top-1 自动加载

2.5 关键指令特征

高质量的 Skill 正文通常具备：

  • imperative 写法（动词开头）而非第二人称
  • 输入契约（哪些必填、哪些可默认）
  • 显式步骤（1、2、3 编号流程）
  • 输出 schema（模板、表单、Markdown 模板）
  • 自检清单（Self-Check）

3. 应用场景

场景Skill 的角色简明示例
领域专精 让通用 AI 瞬间变成"领域专家" 加载法律 Skill 后，AI 回答民法典问题时会援引具体条款 + 案件格式
重复工作流模板 把"概念学习 / 代码审查 / 周报"等流程固化 用户说"整理一下 XGBoost 的学习笔记"，concept-learning Skill 自动按 5 段模板输出
工具集成标准化 统一团队对 Jira / Slack / GitHub 的调用规范 jira-ticket-skill 强制要求先校验 epic、sprint、AC 字段再创建工单
团队知识沉淀 把团队约定沉淀为可分发包 某 FinTech 团队把所有合规检查项打包成 compliance-skill，所有 PR 评审都自动跑
个人跨项目复用 作为"用户级 Skill" 跟随个人 个人投资记录 Skill：用户在任何项目里谈"买入"都会触发持仓记录

4. 边界辨析

区分点Skill相邻概念
位置 上下文之外的外挂指令包 Prompt：在对话或 system prompt内嵌的指令
调用方式 AI 按元数据自主加载 Tool / Function：AI 显式发起函数调用
作用范围 注入知识 + 流程 + 标准 MCP Server：只暴露工具 API
是否改模型 不改变权重，运行时注入 Fine-tuning：永久改变模型参数

4.1 vs Prompt

Prompt 是单次对话的临时指令；Skill 是可复用的、有元数据的、跨会话跨项目的能力包。

用户每天手动在 prompt 里贴 5 段"作诗规则 + 押韵表"，这是 Prompt；把这套规则写进 SKILL.md 并通过描述让模型自动加载，这才是 Skill。

4.2 vs Tool / Function Calling

Tool 是被调用的函数（带输入输出 schema），Skill 是被阅读的说明书（带工作流）。两者常常互补—— Skill 里会告诉模型什么时候该调用哪个 Tool。

"调 get_weather(city) 工具"≠ Skill；而"当用户问出差目的地天气时：先用追问确认出行日期 → 调 get_weather → 如有雨则建议带伞"才是 Skill 应做的事。

4.3 vs MCP Server

MCP（Model Context Protocol）定义了一个工具接入协议；Skill 定义一段知识 + 工作流。MCP 提供"工具箱"，Skill 写明"什么时候、怎么用这些工具箱"。

配置一个 git MCP 服务器后，AI 可以执行 git 命令；但让它在每次改 PR 前先跑 git diff --staged 自检，是 review-skill 才能做到。

4.4 vs Fine-tuning

Fine-tuning 改模型参数，成本高、难迭代；Skill 在外部补内容，热更新、零额外训练成本。

让模型"会写法律意见书"，Fine-tuning 需要上千份判例 + GPU 训练；用合同审查 Skill 注入条款模板 + 风险点 prompt，5 分钟就能上线，效果对 80% 场景已足够。
